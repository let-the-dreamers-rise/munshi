Rs 12,000 went to someone you have never paid, nine minutes after a threat. Munshi noticed, and the first hour is already running.

In that hour, a report on 1930 can still have the money held — if you can produce the reference number, the payee's UPI id and the exact time. All of it is in the bank's own SMS, and nobody who has just been robbed is in any state to go looking.

Munshi reads that SMS, fills in the police report, the bank dispute and the UPI Help complaint, and asks you one question. It never moves money.

Nothing is stored. The run lives in this browser tab and is gone when you close it.

Paste the real SMS from your bank, with a blank line between messages, oldest first. Nothing is stored: the text is read once, in memory, and never written down. You can add from: +9198… or at: 12/09/2026 14:55 as the first line of a message; otherwise Munshi works out which are from a bank and spaces them a few minutes apart.

Munshi Never moves money

What Munshi just did

    Every tool call the agent made, refused ones included. Munshi has no tool that can move money, and a hook refuses anything outside its list.

    How it works

    Five steps, in the order they happen. Everything here is in the repository, and the audit log on the right of the run is the same list of calls, written as they happened.

    1. A witness reads the bank's own SMS

      Ordinary code, no model: it parses the messages into rows — amount, payee, time, reference number, the bank's helpline — and rules decide what deserves a household's attention. Money to a payee never paid before, minutes after a threatening message. A subscription about to renew. The same merchant charging twice.

      It also names the script the message follows — digital arrest, KYC, electricity disconnection, courier and customs, task-and-job, screen sharing — which is the first thing 1930 asks for.

      If the rules see nothing, no agent runs and nothing leaves the phone. The message text itself never travels — only the facts of the one event.

      munshi/witness.py, on top of the MIT-licensed nyaya.money parser.

    2. One Strands agent per event

      Its tools are closures over that event's ledger: investigate the payment, draft the UPI Help complaint, draft the bank dispute, draft the 1930 report, ask the household, remember a trusted payee. A BeforeToolCallEvent hook cancels any call outside the allow-list or with wrong-typed arguments; an AfterToolCallEvent hook records every call, refused ones included.

      There is no tool that moves money, so no message, however worded, can make it move money.

      munshi/agent.py, munshi/policy.py.

    3. It stops in the middle and asks

      When the paperwork is ready the agent calls ask_household, which raises a real Strands interrupt: the tool does not return, the event loop suspends inside that call, and the session is saved as it stands. The card is one line of plain language, in Hindi or English, with two answers.

      Munshi never decides this was a scam on the family's behalf. It is the household's money and the household's word.

      ToolContext.interrupt(), resumed with an interruptResponse.

    4. The pause is portable

      This page is a stateless function. So the whole paused run — inbox, audit log and the suspended Strands session — is gzipped into roughly thirteen kilobytes of text and handed to your browser tab. Answer, and it comes back, the session is rebuilt, and that same tool call finally returns your answer.

      Nothing is kept on the server. Close the tab and the run is gone. Running on a phone or a home server it is the same code with a directory instead of a string, and the answer can come hours later.

      munshi/portable.py, munshi/web.py.

    5. It hands off to the people who can actually act

      1930 and cybercrime.gov.in for the police report, the bank's own helpline from the bank's own SMS, and UPI Help for the NPCI complaint — each one filled in with the reference number, the payee's UPI id and the exact time, in English because that is what the forms take.

      Munshi prepares and hands over. It cannot file anything for you, and it does not pretend to be the authority.

      munshi/complaints.py, and the call and copy buttons on the card itself.

    What it will never do

    • Move, hold or refund money — there is no such tool, and the hook refuses anything off the list.
    • Decide on the family's behalf. Every irreversible step waits behind the question.
    • Send the message text anywhere. Only the event's own facts leave the phone.
    • Keep your run. On this site it lives in your tab; on a phone, on your phone.

    Munshi is open source (MIT): github.com/let-the-dreamers-rise/munshi. Built on Strands Agents for the AWS Agents for Humans hackathon. Not affiliated with NPCI, the Indian Cyber Crime Coordination Centre or any bank. Munshi prepares complaints; it cannot file them for you, and it never moves money.

    This demo runs the agent with Munshi's playbook model, which follows the system prompt with no weights, so anyone can run the real loop — the Strands event loop, the policy and audit hooks, the interrupt and the resumed session — without an AWS account. With credentials it runs on Amazon Bedrock instead; nothing else changes.
