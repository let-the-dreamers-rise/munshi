Rs 12,000 went to someone you have never paid, nine minutes after a threat. Munshi noticed, and the first hour is already running.

In that hour, a report on 1930 can still have the money held — if you can produce the reference number, the payee's UPI id and the exact time. All of it is in the bank's own SMS, and nobody who has just been robbed is in any state to go looking.

Munshi reads that SMS, fills in the police report, the bank dispute and the UPI Help complaint, and asks you one question. It never moves money.

Nothing is stored. The run lives in this browser tab and is gone when you close it.

Paste the real SMS from your bank, with a blank line between messages, oldest first. Nothing is stored: the text is read once, in memory, and never written down. You can add from: +9198… or at: 12/09/2026 14:55 as the first line of a message; otherwise Munshi works out which are from a bank and spaces them a few minutes apart.

What Munshi just did

    Every tool call the agent made, refused ones included. Munshi has no tool that can move money, and a hook refuses anything outside its list.

    On the phone

    A deterministic witness turns bank SMS into events. Message text never leaves the device — only amounts, payees and times.

    In the agent

    A Strands agent investigates, drafts the paperwork, and pauses on a real interrupt to ask the family. The paused session is saved, so the answer can come hours later.

    To the right people

    1930, the bank's own helpline and UPI Help. Munshi prepares; you act. It hands off rather than pretending to be the authority.

    Munshi is open source (MIT): github.com/let-the-dreamers-rise/munshi. Built on Strands Agents for the AWS Agents for Humans hackathon. Not affiliated with NPCI, the Indian Cyber Crime Coordination Centre or any bank. Munshi prepares complaints; it cannot file them for you, and it never moves money.

    This demo runs the agent with Munshi's playbook model, which follows the system prompt with no weights, so anyone can run the real loop — the Strands event loop, the policy and audit hooks, the interrupt and the resumed session — without an AWS account. With credentials it runs on Amazon Bedrock instead; nothing else changes.
